StitchAI: An Autonomous AI Platform for Custom Apparel, Sales, and Production Orchestration

Department of Computer Science & Intelligent Manufacturing Systems

Published: October 2026 • Document ID: STITCHAI-THESIS-REV-3.5

Abstract

The customized apparel and embroidery sector is characterized by fragmented manual communications, repeated quote negotiation latency, opaque production visibility, and inefficient digitizing file transfers. This paper presents StitchAI, an integrated autonomous software architecture unifying Large Language Model (LLM) conversational agents, computer vision vector stitch analysis, algorithmic multi-tier quotation models, relational data persistence, payment gateway automation, and a decentralized production marketplace into a cohesive digital operating system.

Keywords: Large Language Models, RAG, AI Receptionist, Computer Vision, Custom Apparel, Embroidery, Tajima DST, Dynamic Pricing, B2B SaaS, SQLite, Stripe Checkout.

1. Mathematical Formulations & Algorithms

1.1 Computer Vision Vector Stitch Estimation Formula

The total stitches \(S_{\text{total}}\) required to embroider an uploaded vector graphic is formulated as the sum of the surface area Tatami fill stitches and perimeter Satin border stitches:

$$S_{\text{total}} = \left( A \cdot \rho_{\text{tatami}} \cdot \gamma_{\text{fill}} \right) + \left( P \cdot \rho_{\text{satin}} \right) + (N_c \cdot \tau_{\text{tie}})$$

Where \(A\) is graphic bounding area (in²), \(\rho_{\text{tatami}} \approx 1,750\,\text{stitches/in}^2\) is Tatami grid density, \(\gamma_{\text{fill}} \approx 0.55\) is fill coverage coefficient, \(P\) is perimeter boundary (inches), \(\rho_{\text{satin}} \approx 160\,\text{stitches/linear in}\), \(N_c\) is thread color count, and \(\tau_{\text{tie}} = 120\) represents automated tie-in/tie-off stitches.

1.2 Perceptually Weighted Euclidean Thread Color Matching

To map detected raster RGB pixels to the nearest standard Madeira Polyneon 40 thread catalog color:

$$\Delta E_{\text{thread}} = \sqrt{ 2(R_1 - R_2)^2 + 4(G_1 - G_2)^2 + 3(B_1 - B_2)^2 }$$

1.3 Algorithmic Dynamic Unit Pricing Equation

$$P_{\text{unit}}(Q, S, K) = \left[ B(Q) + \left(\frac{S}{1000} \cdot R_s\right) + (K - 1) \cdot C_m + C_{\text{packaging}} \right] \cdot M_{\text{velocity}}$$

Where \(B(Q)\) is quantity-tiered base garment knit cost, \(S\) is stitch count, \(R_s = \$0.18\) run fee per 1k stitches, \(K\) is number of embroidery placements, \(C_m = \$3.20\) multi-placement fee, and \(M_{\text{velocity}} \in \{1.0, 1.15, 1.30\}\) represents production turnaround speed multiplier.

2. Relational Database Schema Architecture

StitchAI utilizes a persistent relational database (SQLite/PostgreSQL) with 6 core tables ensuring ACID compliance across concurrent customer orders and factory dispatch queues:

TABLE: orders • id: TEXT (PK)
• client: TEXT
• garment: TEXT
• quantity: INTEGER
• stitch_count: INTEGER
• current_stage: INTEGER (0-7)
• total_price: REAL
• payment_status: TEXT
TABLE: transactions • id: TEXT (PK)
• order_id: TEXT (FK)
• amount: REAL
• payment_gateway: TEXT (Stripe/Razorpay)
• status: TEXT
